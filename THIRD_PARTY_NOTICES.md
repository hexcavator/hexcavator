## LLVM Project

- Source: <https://github.com/llvm/llvm-project>
- License: Apache License 2.0 with LLVM Exceptions
  ([`crates/symbols/demangle/LICENSE-LLVM`](crates/symbols/demangle/LICENSE-LLVM), and the
  same text in each other crate with LLVM-derived parts:
  [`crates/isa/arm64`](crates/isa/arm64/LICENSE-LLVM),
  [`crates/isa/x86`](crates/isa/x86/LICENSE-LLVM),
  [`crates/debug/unwind`](crates/debug/unwind/LICENSE-LLVM),
  [`crates/symbols/dwarf`](crates/symbols/dwarf/LICENSE-LLVM),
  [`crates/formats/elf`](crates/formats/elf/LICENSE-LLVM), and
  [`apps/hexcavator`](apps/hexcavator/LICENSE-LLVM))
- Product code: the Itanium C++ demangler (`crates/symbols/demangle/src/itanium`)
  and the Rust demangler (`crates/symbols/demangle/src/rust/`) follow the grammar
  and printing rules of LLVM's `ItaniumDemangle.h` and `RustDemangle.cpp`;
  those files carry `SPDX-License-Identifier: Apache-2.0 WITH
  LLVM-exception`. The ARM64 instruction tables
  (`crates/isa/arm64/tables/a64.txt`) take operand meanings from LLVM's AArch64
  target (its TableGen records, dumped with `llvm-tblgen --dump-json`) and
  decoding rules from its disassembler, printer, and assembler checks
  (`AArch64Disassembler.cpp`, `AArch64InstPrinter.cpp`,
  `AArch64AsmParser.cpp`, `AArch64BaseInfo.h`). The compact unwind
  encodings' meaning (`crates/debug/unwind/src/apple_compact.rs`) follows libunwind's
  `CompactUnwinder.hpp` and `compact_unwind_encoding.h`. The DWARF constants
  names (`crates/symbols/dwarf/src/spelling.rs`) are generated from LLVM's
  `Dwarf.def` and `Dwarf.h` (by `tools/dwarf/names.py`), and `hexc dwarf`'s
  type names (`apps/hexcavator/src/dwarfdump/types.rs`) port the rules of
  LLVM's `DWARFTypePrinter.h`. The ELF constants' names
  (`crates/formats/elf/src/spelling.rs`) are generated from LLVM's
  `BinaryFormat/ELF.h`, `ELF.def`, `DynamicTags.def`, and `ELFRelocs/*.def`
  (by `tools/elf/names.py`), and `hexc dump`'s ELF, Mach-O, and WebAssembly
  output (`apps/hexcavator/src/dump/readobj`) follows llvm-readobj's
  (`ELFDumper.cpp`, `MachODumper.cpp`, `WasmDumper.cpp`). The x86 tables'
  AMD AVX512_BMM lines (`crates/isa/x86/tables/05-evex.txt`) come from
  LLVM's `X86InstrAVX512.td`. Under the LLVM Exceptions, binaries need not
  reproduce the notice; `hexc licenses` prints it anyway.
- Test data: `crates/symbols/demangle/tests/data/itanium-cases.inc` is libc++abi's
  `DemangleTestCases.inc`, unmodified. `crates/symbols/demangle/tests/data/rust-v0.txt`
  pairs Rust symbol names with `llvm-cxxfilt`'s demanglings of them.
- LLVM tools (`llvm-readobj`, `llvm-objdump`, `llvm-dwarfdump`, `llvm-nm`,
  `llvm-cxxfilt`, `dsymutil`, `llvm-lipo`, `clang`, `lld`) build test inputs
  and produce the expected outputs in `testdata`; none of their code is
  included.

## Arm architecture specifications

- Source: <https://developer.arm.com/Architectures/A64%20Instruction%20Set%20Architecture>
  and Arm's Machine Readable Specification (AARCHMRS)
- `crates/isa/arm64/tables/sysregs.txt` is generated from AARCHMRS
  `Registers.json`, under the BSD 3-Clause License
  ([`crates/isa/arm64/LICENSE-ARM`](crates/isa/arm64/LICENSE-ARM)); binaries must
  reproduce that notice, which `hexc licenses` does.
- `crates/isa/arm32/tables/aarch32.txt` is generated by `tools/arm32/extract.py`
  from AARCHMRS's `Instructions.json` (A32 and T32), with the same license
  ([`crates/isa/arm32/LICENSE-ARM`](crates/isa/arm32/LICENSE-ARM)).
- `crates/isa/arm64/tables/a64.txt` is generated by `tools/arm64/extract.py`
  from AARCHMRS `Instructions.json` (encodings, feature conditions,
  assembler syntax, and aliases; BSD 3-Clause) and LLVM's AArch64 target
  (see above). Each operand line says which of the two it came from. Arm's
  proprietary A64 ISA XML is not used.
- The downloaded specifications themselves are not redistributed: they
  are kept apart from the repository, with the extended tests.

## Root certificates

- `crates/formats/signature/roots/*.cer` are the public root certificates
  of Microsoft, Apple, and the public code-signing and timestamping
  authorities. `tools/signature/roots.py` downloads them from Microsoft's
  root program and from Apple, unmodified, and checks each one's
  thumbprint. `hexc signature` bundles them to check signatures.

- Source: <https://github.com/abseil/abseil-cpp>
- License: Apache License 2.0
- Test data: `crates/symbols/demangle/src/itanium/tests.rs` checks the short form

## bloaty

- Source: <https://github.com/google/bloaty>
- License: Apache License 2.0
- Not included. `crates/analysis/size` reproduces bloaty's reports (its data
  sources, labels, and rules), and `tools/bloaty` builds bloaty from a
  separate clone and compares the two reports; where bloaty is wrong, hexc
  differs, as each size module documents.
